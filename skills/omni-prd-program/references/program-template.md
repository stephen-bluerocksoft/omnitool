# program.md template

`program.md` coordinates the epics one PRD becomes. It is a durable document in the program
directory, read by people deciding what to plan next and by this skill's epic mode, which takes an
epic's scope from it. It is written for the product owner and the PM: plain language, requirement
IDs where they help, no task lists.

Fill every `[BRACKET]`, delete the guidance lines, and drop a section only where the guidance says
it is optional.

What never goes in it:

- **Run state.** No "in progress", "complete", percentages, dates of runs, or devbot run ids. Status
  lives in each epic's `manifest.yaml` and in devbot. Whether an epic's directory exists is a link,
  not a status, and may be shown as one.
- **Per-file inventories or counts** of the codebase. Cite the files that settle a question; do not
  list a directory.
- **Lists of values already taken** in a shared namespace (ids in use, spec numbers claimed). They
  drift the day after the plan is written. State the rule and how to check it instead. What a
  planned epic will add ("`records-hold` adds the `no_records` source") is a cross-epic assignment,
  not a taken value, and belongs.
- **Plans for work another team or track owns.** Name the interface this program needs from it and
  stop there.
- **People's names** for other tracks. Refer to a track by its specs and branches.

```markdown
# [Program name]: Program Plan

Status: proposal, [date]. Generated by `omni-prd-program` from [`[PRD file]`]([relative link]),
reconciled against `[target repo]` @ `[git ref]` on `[branch]`[, with `[other branch]` @ `[ref]` read
in place]. Nothing here is decided until the product owner reviews it; open questions carry the
default this plan assumes.

Detailed design: [design.md](design.md). Epic documents: `[epic docs root]/<epic>/`.

## Goal

[Two short paragraphs from the PRD: the outcome and why it matters. No requirement IDs here.]

## Epics

| Order | Epic | PRD scope | Depends on | Blocked by (outside the repo) |
| ----- | ---- | --------- | ---------- | ----------------------------- |
| 1 | `[epic-slug]` | [PRD epics, sections, ID ranges] | [epic slugs, or --] | [what it cannot deliver its core without -- or none. Inputs with safe defaults go under Outside dependencies, not here] |

[Guidance: start from the PRD's own epic list and phase plan. One row per epic; an adopted epic
(its directory already exists) links its overview.md in the Epic cell, followed by "(on
`<branch>`)" when the documents live on another branch.]

### `[epic-slug]`

[One paragraph per epic, product level: what a user can do when it is done, and its boundary with
its neighbours. Name the PRD items it owns at full width. For an adopted epic, describe what was
actually built, not what its seed proposed. For a planned epic, end with its rough size (small,
medium, or large -- roughly three, six, or nine units).]

## Order and its reasons

[How this order compares with the PRD's own sequencing (phase plan, sprint plan, epic numbering).
List every departure with its reason. "Too large for one epic" justifies a split; it never
justifies moving a PRD item later than the PRD's own phase without saying so here.]

## PRD coverage

[Every inventoried PRD item, one row each, in PRD order. Owner names every epic that carries the
item, or "all epics". Status is one of:
- covered -- the owners deliver the item at the PRD's full width: built in an adopted epic, or
  given to a planned epic at full width. For a non-goal, the boundary holds in every epic
- deferred -- covered, but the owner runs later than the PRD places the item: its epic is ordered
  after epics that hold items from a later PRD phase or sprint. An item the PRD runs "in parallel"
  is deferred only when the plan starts it later than the PRD does. The departure is listed under
  "Order and its reasons"
- narrowed -- the owners deliver less than the item says; Decision cites who decided and where
- dropped -- nothing delivers it; Decision cites who decided and where
- open -- the width or the owner depends on an open question below; Decision names the question
- awaiting input -- the row is itself an outside input that has not arrived (a firm-supplied list, a
  vendor, a platform capability, a PRD open decision with no plan question); Decision names who owes
  it. Once this plan carries a default for it in an open question, the row is "open" instead
One status per row. When several apply, use the first that fits in this order: dropped, narrowed,
open, awaiting input, deferred, covered -- the earliest is what someone must act on. Mention the
others in Decision.
A "narrowed" or "dropped" row with no cited decision is a defect: make it "open" instead.]

| Item | PRD text (short quote) | Owner | Status | Decision or evidence |
| ---- | ---------------------- | ----- | ------ | -------------------- |
| [ID, section, figure, or acceptance criterion] | "[quote]" | `[epic-slug]` | covered | [PRD ref, decision ref, or code evidence] |

[If this matrix would push program.md past about 600 lines, it lives in coverage.md beside this file.
coverage.md opens with a title ("[Program name]: PRD Coverage"), the same Status paragraph as
program.md, a link back to program.md, then the status legend and the table; Sources stay in
program.md. This section then becomes a one-paragraph summary of the rows that are not "covered",
with the link.]

## Cross-epic decisions and contracts

[Things more than one epic produces or consumes: a shared record or state machine, a timer
mechanism, a consent or approval policy, an event or timeline model, a permission model. For each:
what it is, which epic establishes it, which epics rely on it, and whether it is decided. Details
belong in design.md -- link the section.]

## Shared namespaces

[Optional -- only when the repo allocates numbered or named slots that several epics draw from:
workflow or job ids, spec numbers, migration chains, module or route prefixes. For each, state the
rule, what goes wrong when it is broken, and how to check what is taken (the file, command, or
branches to look at) -- not the taken values themselves. Omit the section when nothing is shared.]

## Outside dependencies

| Dependency | Needed by | From whom | PRD reference |
| ---------- | --------- | --------- | ------------- |
| [firm input, vendor, credential, platform capability] | `[epic-slug]` | [owner role, team, or vendor] | [section or OD id] |

## Other tracks

[Optional -- only when other work in the repo touches the same areas. For each: the track, the
interface this program needs from it, and what is agreed. Never assign it work.]

## Findings

[Where existing epics or documents differ from the PRD or from the code: a narrowing with no
decision, something built that no PRD item asks for, reserved structure, a stale epic document, a
program input that is not version-controlled, a proposed addition to an existing design.md. One
bullet per finding: what the PRD says, what exists instead, whether a recorded decision covers it,
and the recommended action (accept and record the decision, change a spec, schedule in a named epic,
or remove). Omit the section when there is nothing to report.]

## Decisions

| # | Question | Decision | Decided by, date |
| - | -------- | -------- | ---------------- |
| [n] | [the question as it was asked] | [the answer, and what it changed in this plan or design.md] | [product owner, in the omni-prd-program session, date] |

[Every program-mode question, once answered. Keep its number from Open questions so citations in the
coverage rows stay valid. Decisions are never deleted; a later reversal is a new row that names the
one it reverses.]

## Open questions

| # | Question | Default assumed until then | Resolves at | Affects | Who decides |
| - | -------- | -------------------------- | ----------- | ------- | ----------- |
| [n] | [question] | [default] | [`<epic>` seed, `<epic>` /devbot-plan, or run time] | `[epic-slug]` | [product owner, PM, firm, platform team] |

[Only questions a later stage owns, recorded so that stage finds them. A program-mode question never
stays here: it is asked and moves to Decisions -- unless no one could be asked, when it stays with
"unanswered" in Resolves at. Outside inputs are "awaiting input" coverage rows, not questions.]

## Sources

- PRD: [path], sections read in full, figures 1 to [N].
- [Existing epic documents, design documents, specs, and code read, named exactly.]
```
